# Правила тестирования в tests/

Действуют, когда агент читает или изменяет файлы в каталоге `tests/`.
Правила из корневого `AGENTS.md` остаются обязательными; этот файл дополняет их.

## Структура тестов

- Каждый модуль production-кода — отдельная тестовая цель на Qt Test.
- Модуль = класс или небольшой связный компонент с самостоятельным контрактом.
- Изменение без теста допустимо только для декларативной конфигурации/документации
  или физически нетестируемого тонкого entry point. Исключение обосновывается письменно.

## Обязательное покрытие

- happy path;
- границы, пустые значения и некорректный ввод;
- ошибки и сохранение инвариантов;
- сигналы Qt через `QSignalSpy` (если часть контракта);
- повторные вызовы, владение и жизненный цикл (если существенно);
- регрессионный сценарий для каждого исправленного дефекта.

## Правила тестов

- Arrange–Act–Assert, один наблюдаемый контракт на тест.
- Детерминированность: без реальной сети, микрофона, часов, случайности и внешних сервисов.
- Никаких `sleep`; асинхронность — через `QTRY_*` с разумным timeout.
- Тесты не зависят от порядка запуска и общего изменяемого состояния.
- Тестовые двойники реализуют узкие интерфейсы, не наследуют concrete-классы.
- GUI/QML-тесты — offscreen.
- Каждый тест регистрируется через CTest.

## Gate

**100% новых/изменённых ветвей бизнес-логики** покрыты тестами.
Не писать бессмысленные тесты ради метрики. Не менять ожидания теста для подгонки
под дефектную реализацию.
