## [Unreleased]

### Changed

- Живой ответ в чате больше не перепарсивает весь накопленный Markdown на каждом
  чанке: сырой текст по-прежнему дописывается мгновенно (O(1) на чанк), а
  санитизированная разметка (`SafeMarkdown`) пересчитывается лениво и оповещает
  QML не чаще одного раза в 80 мс (и безусловно на terminal-сигнале
  `completed`/`failed`/`cancelled`/`destroyed`). Пересчёт по полному тексту
  остаётся O(длина ответа) на тик, но число тиков ограничено временем стрима, а
  не числом чанков, поэтому квадратичный по чанкам рост нагрузки на GUI-поток
  устранён. Итоговая разметка побайтово совпадает с `SafeMarkdown` полного
  текста: после завершения `streamingMarkup` (сохраняется до следующего `send()`)
  и `markup` добавленного сообщения равны. Покрыто тестами `tst_chat`
  (коалесцинг, flush на terminal, независимость от троттлинга, побайтовая
  идентичность) и QML smoke в `tst_main`; `streamingMarkup` теперь имеет
  собственный сигнал `streamingMarkupChanged`.
- `qmlformat` для check-режима берётся из проектного Qt (6.8.3) так же, как
  `qmllint`, и только при его отсутствии — из дистрибутивного qt6-tools:
  дистрибутивный 6.4.2 портит валидный Qt 6 QML (у `pragma ComponentBehavior: Bound`
  теряется значение) и в check-режиме отвергал бы корректно отформатированный
  файл. Затронуты `scripts/static-analysis.sh` и `.pre-commit-config.yaml`.
- По замечаниям ревью PR #18: инвариант «не отправлять пустое сообщение»
  перенесён в домен — `Chat::send` игнорирует пустой текст, поэтому `Composer`
  больше не фильтрует его в JS (view стал глупее, а инвариант enforced на границе
  домена). `PlaceholderProvider` подчищен: чистый помощник вынесен свободной
  функцией в анонимный namespace вместо `static`-члена, а комментарий приведён к
  фактическому поведению (ответ приходит одним чанком из цикла событий).
- Сборка QML-слоя приведена к одному целевому таргету: `audio-assistant-domain`
  стал backing-таргетом QML-модуля `AudioAssistant`, отдельный таргет
  `audio-assistant-qml` удалён. C++-типы домена и есть view models, поэтому
  отдельная библиотека-адаптер не нужна; для статического QML-модуля
  генерируемый плагин (`audio-assistant-domainplugin`) линкуется в приложение и
  в GUI-тесты, иначе движок не видит зарегистрированные типы.
- В `audio-assistant-qt-warnings` добавлены подавления для генерируемого Qt-кода
  QML-модуля (qrc-инициализаторы, qmlcachegen, регистрация типов):
  `-Wno-global-constructors`, `-Wno-exit-time-destructors`,
  `-Wno-missing-prototypes`, `-Wno-extra-semi-stmt` — эти конструкции создаёт Qt,
  вручную они не переписываются.
- `scripts/static-analysis.sh` и `.pre-commit-config.yaml` запускают `qmllint` из
  того же Qt, против которого собирается модуль (проектный Qt 6.8.3), и
  передают `-I` для сгенерированного `qmldir`/`*.qmltypes`. Системный
  qt6-tools 6.4.2 не умеет разбирать `qmltypes` проектного модуля и отвергал
  валидный QML; `qmlformat` обеих версий даёт идентичный результат.
- LLMQore больше не подтягивается через `FetchContent` в `CMakeLists.txt`: библиотека
  поставляется Conan-пакетом `llmqore/0.8.0` из in-repo рецепта `recipes/llmqore`
  (пин на upstream-тег `v0.8.0`). Conan стал обязательным для сборки, а загрузка
  исходников с `github.com` переехала с этапа конфигурации CMake на этап
  `conan install`; зависимости линкуются через `find_package(LLMQore)`.
- Профиль `profiles/clang18` теперь явно задаёт `tools.build:compiler_executables`
  (`clang-18` / `clang++-18`), чтобы пакеты, которые собирает Conan (llmqore, spdlog),
  действительно компилировались Clang, а не системным компилятором по умолчанию.
- CI-стадия Static Analysis больше не анализирует заголовки отдельно: `clang-tidy`
  в workflow приведён к локальному зеркалу (`scripts/static-analysis.sh`) и стадии
  `clazy` — проверяются только translation units (`*.cpp`), а заголовки разбираются
  через включающие их TU (диагностика в них по-прежнему видна благодаря
  `HeaderFilterRegex`). Лишний разбор заголовков без собственной команды компиляции
  заметно удлинял стадию; таймаут стадии поднят с 30 до 45 минут, чтобы анализ
  успевал завершиться на растущей кодовой базе (предыдущие мержи в `main` уже
  отменялись по 30-минутному лимиту).

### Fixed

- Текст стримингового ответа LLM больше не вылезает за границы чата во время
  рассуждений: живая реплика стала футером списка сообщений и теперь обрезается
  и прокручивается вместе с транскриптом вместо того, чтобы рисоваться поверх
  соседних панелей и окна. До завершения ответа длинный текст оставался вне
  панели, а после — попадал в чат как обычное сообщение.
- Окно приложения больше не зависает невидимым: добавлено свойство `visible: true` в `ApplicationWindow` (`qml/Main.qml`). Ранее окно создавалось, но не отображалось.
- Локальная генерация coverage-отчёта больше не зависает на сетевых запросах:
  `llvm-profdata` и `llvm-cov` запускаются с отключённым debuginfod
  (`env -u DEBUGINFOD_URLS`). При выставленном `DEBUGINFOD_URLS` (по умолчанию в части
  окружений Ubuntu) `llvm-cov` блокировался на загрузке отладочной информации системных
  библиотек; собственные объекты проекта несут DWARF сами.
- `CodeChecker analyze` в `scripts/static-analysis.sh` получал недопустимый аргумент
  `--analyzers clang-tidy,cppcheck` (анализаторы передаются через пробел).

### Added

- Ответы ассистента в LLM-чате рендерятся как Markdown (заголовки, жирный/курсив,
  списки, код, ссылки), а не как голый текст с `**`: сообщение ассистента
  отображается `Text.MarkdownText`, а собственное сообщение пользователя —
  `Text.PlainText` по роли `isUser`. Санитизация недоверенного контента вынесена
  в C++ (тестируемо), QML только сопоставляет роль и формат. Новый доменный
  объект-значение `SafeMarkdown` (`src/domain/`) использует встроенный парсер Qt
  (`QTextDocument::setMarkdown` с `MarkdownNoHTML`) без сторонних библиотек и
  собственного парсера: HTML/`<script>` не интерпретируется, а показывается
  литеральным текстом; markdown-картинки `![…](url)` и `<img>` удаляются и не
  тянут сеть; ссылками остаются только схемы http/https, а `javascript:`/`data:`/
  прочие и относительные цели разворачиваются в обычный текст без кликабельности.
  Модель `Chat` получила роль `markup` (санитизированный текст для отображения,
  пользовательский — дословно) и свойство `streamingMarkup` для «живого» хвоста
  ответа; `Message` остаётся неизменяемым. Санитизированная строка мемоизируется
  (на сообщение и на текущий стрим), поэтому роль `markup` не перепарсивает текст
  на каждое обращение. Тесты: `tst_safe_markdown`
  (санитизация и повторный разбор вывода тем же диалектом, что и рендерер),
  дополнения в `tst_chat` (роль `markup`, мемоизация, `streamingMarkup`) и QML
  smoke в `tst_main` (формат делегата по роли, нейтрализация опасного содержимого,
  санитизированный стриминг).

- Ошибки LLM-чата теперь видны в интерфейсе: при сетевом сбое, неверном
  API-ключе, превышении rate-limit, таймауте или некорректном ответе панель чата
  показывает причину красным текстом рядом с полем ввода, а не молчит. Причина —
  транзиентное состояние `Chat` (`errorText`/`hasError`): типизированный
  `ProviderError` переводится в понятный текст, новый запрос сбрасывает ошибку,
  а отмена ошибкой не считается. Покрыто тестами `tst_chat` и QML smoke
  `tst_main`.
- Кольцевой аудиобуфер `AudioBuffer` (`src/audio/`) — реализация порта
  `AudioSink`, хранящая последние N секунд PCM. Ёмкость задаётся явно в кадрах
  или через длительность + `AudioFormat` (`ceil(duration * sampleRate *
  channels)`); нулевая/отрицательная длительность и нулевая ёмкость отклоняются
  при создании. Стор хранится в `std::vector<float>`, выделенном один раз при
  конструировании, поэтому `write()` не аллоцирует и не блокирует (годится для
  real-time аудиоколбэка) и перезаписывает самые старые кадры при переполнении.
  Модель потокобезопасности — SPSC: `write()` вызывается одним capture-потоком,
  `snapshot()` возвращает независимую копию кадров в хронологическом порядке и
  читает через seqlock (odd/even счётчик), поэтому снимок всегда согласован, а
  писатель никогда не ждёт читателя. Зависимостей, кроме STL, нет.
- Тест `tests/tst_audiobuffer.cpp` (цель `tst_audiobuffer`, зарегистрирована в
  CTest): ёмкость и инварианты, порядок при недозаписи/ровно ёмкости/переполнении,
  обёртка кольца, пустой ввод, независимость снимка и согласованность при
  конкурентных `write()`/`snapshot()`.

- Настройка провайдера в UI (шестой инкремент LLM-чата): endpoint и модель
  задаются и сохраняются в панели «Provider settings», не только через
  окружение. Введённые `baseUrl`/`model` персистятся в env-совместимый
  KEY=VALUE-файл `provider.env` в каталоге пользовательской конфигурации
  (`QStandardPaths::AppConfigLocation`); путь инжектируется, поэтому тесты
  используют временный каталог. При старте composition root (`main()`) читает
  файл и реальное окружение, причём переменные окружения
  (`POLZA_BASE_URL`/`POLZA_MODEL`) имеют приоритет по каждому значению.
- `ProviderSettings` (`src/domain/ProviderSettings.h`) — QML-совместимый
  объект конфигурации (`baseUrl`/`model` + сессионный ключ). Свойства
  read-only, а единственный мутирующий метод — явная команда
  `save(baseUrl, model, apiKey)`: она нормализует и валидирует черновик целиком,
  пишет endpoint+model, затем заменяет состояние как единое значение
  (copy-and-modify); отклонённый save не меняет ни состояние, ни файл. Форма в
  QML держит черновик полей локально. Сохранение endpoint/model не зависит от
  наличия секрета, а для ключа наружу отдаётся лишь булев признак
  `isKeyConfigured`, поэтому «сохранить url/model без ключа» нельзя
  заблокировать. Рецепты провайдеров читают настройки в момент `fresh()`,
  поэтому новый чат использует сохранённые значения; `Providers` остаётся
  неизменяемым и держит только не-владеющую ссылку на настройки, которыми владеет
  composition root.
- Персистенс без секретов: `ProviderConfigFile` и `ProviderConfigSource`
  (`src/domain/`) пишут и читают только endpoint и модель; API-ключ никогда не
  попадает в файл (строка `POLZA_API_KEY` в нём отсутствует) — он приходит только
  из окружения или из маскированного поля UI (`echoMode: TextInput.Password`),
  живёт в памяти сессии и является write-only для QML: поле передаёт ключ в C++
  только по команде `save(...)` (пустое поле сохраняет уже имеющийся ключ), а
  читаемого QML-свойства со значением ключа нет. Пустые/некорректные
  значения (пустой URL, относительный или не-http(s) URL, пустая модель, перевод
  строки) отклоняются при сохранении с честным сообщением, файл конфигурации при
  этом не трогается.
- Тесты `tst_provider_config` (чтение/запись конфиг-файла во временном каталоге,
  приоритет env над файлом, игнорирование ключа из файла, malformed-строки,
  некорректные значения) и `tst_provider_settings` (валидация и сигналы
  настроек, «сохранил → новый чат использует введённый url/model» против
  in-process mock-сервера, ключ не попадает в файл). QML smoke в `tst_main`
  проверяет маскирование ключа и сохранение настроек из панели.
- Сетевой провайдер LLM-чата (четвёртый инкремент плана):
  `OpenAiCompatibleProvider` (`src/app/`) — адаптер над сторонним
  `LLMQore::OpenAIClient`, реализующий доменный интерфейс `Provider`. Вся
  трансляция инкапсулирована в адаптере: `std::vector<Message>` →
  `LLMQore::Conversation`, а сигналы LLMQore
  (`chunkReceived`/`requestFinalized`/`requestFailed`) → доменный `Answer`
  (`appendChunk`/`complete`/`fail`). Типы LLMQore не протекают в domain/UI
  (в заголовке — только forward declaration). `Answer::cancel()` через сигнал
  `cancelled()` гасит реальный сетевой запрос (`OpenAIClient::cancelRequest`)
  без изменения контракта `Provider`/`Answer` и без контроллера; сбои LLMQore
  классифицируются в типизированный `ProviderError`
  (`kNetwork`/`kAuthentication`/`kRateLimit`/`kInvalidResponse`/…), детали
  остаются в тексте `fail`.
- Конфигурация сетевого провайдера читается composition root'ом (`main()`) из
  окружения (`POLZA_BASE_URL`/`POLZA_API_KEY`/`POLZA_MODEL`) и передаётся в
  рецепт `ProviderOffer`; значения не хардкодятся, ключ не попадает в исходники,
  QML, логи и Git. При отсутствии ключа/endpoint провайдер не падает, а честно
  сообщает об ошибке (`kAuthentication`/`kUnknown`); при наличии конфигурации
  приложение стримит ответ. В список `Providers` добавлен сетевой провайдер
  рядом с offline-заглушкой.
- Тесты `tst_openai_provider` (Qt Test + CTest, offscreen, детерминированно, без
  внешней сети): адаптер проверяется сквозным сценарием против локального
  OpenAI-совместимого mock-сервера на `QTcpServer` (`tests/OpenAiMockServer`) —
  стриминг чанков и завершение, отображение истории и модели в тело запроса,
  HTTP-ошибки 401/429/500/400, malformed JSON в SSE, обрыв потока посередине,
  отмена с реальным разрывом соединения и таймаут. Mock-сервер — двойник
  проводного протокола, не наследующий ни один project/LLMQore-тип.
- Контракты слоя захвата аудио (`src/audio/`, статическая библиотека
  `audio-assistant-audio`): неизменяемый `AudioFormat` (частота дискретизации, число
  каналов, формат выборки f32; инварианты «частота > 0, каналы > 0» проверяются при
  создании), ролевой интерфейс `AudioSource` (`start`/`stop`/`format`) и порт
  `AudioSink` (`write` — non-blocking, без аллокаций и блокировок, вызывается из
  real-time аудиоколбэка). Модуль не зависит от Qt и платформенного кода; `miniaudio`,
  Conan и существующая domain/QML-логика не затронуты. Канонический формат захвата —
  16 кГц, mono, f32. Модульный тест `tst_audioformat` (Qt Test + CTest, offscreen):
  создание, инварианты, границы диапазонов и сравнение.
- QML-слой LLM-чата (третий инкремент плана): `Chat` стал моделью сообщений для
  QML — `QAbstractListModel` поверх неизменяемого `std::vector<Message>`
  (append-only: строки только вставляются, роли `text` и `isUser`), при этом
  живой ответ остаётся отдельными свойствами `streamingText` и `streaming` и не
  попадает в историю до `completed`. C++-типы `Chat`, `Chats`, `Providers`,
  `Message` и `NewChat` зарегистрированы в QML-модуле `AudioAssistant`
  (`QML_ELEMENT` + `qt_add_qml_module`); чаты помечены C++-владением, чтобы
  движок не забрал себе объекты, которыми владеет сетка.
- Тонкий QML-интерфейс чата из компонентов (`qml/`): `Main` (композиция),
  `ProviderSelector` (выбор провайдера + намерение «добавить чат»), `ChatGrid`
  (сетка независимых чатов), `ChatPanel` (ячейка: шапка, отмена, транскрипт,
  ввод), `ConversationView` (лента сообщений и стриминг), `MessageDelegate`
  (одно сообщение) и `Composer` (ввод + отправка). Цвета, отступы и типографика —
  через синглтон токенов `Theme`; у интерактивных элементов заданы
  accessibility-имена.
- `NewChat` (`src/domain/NewChat.h`) — тонкий инвокабл, закрывающий ключевой
  вопрос инкремента: QML не может ни вызвать `Providers::fresh(id)`
  (`std::unique_ptr`), ни передать провайдера в `Chats::add`, поэтому ровно одна
  композиция `chats.add(providers.fresh(id))` инкапсулирована в этом объекте без
  состояния, а composition root (`main()`) решает, с какой сеткой и списком он
  работает.
- Композиция приложения в `main()` (composition root): сетка `Chats`, список
  `Providers` с рецептом провайдера и `NewChat` создаются и внедряются в QML
  через `setInitialProperties`; QML ничего не конструирует сам.
- `PlaceholderProvider` (`src/app/`) — честно помеченный локальный in-memory
  провайдер-заглушка («Placeholder (offline)»), отвечающий эхом и кормящий
  `Answer` из цикла событий. Сеть и `PolzaProvider` — следующий инкремент.
- Тесты: `tst_newchat` (композиция `open`, владение, независимость экземпляров,
  неизвестный id, «рецепт не собрал провайдера»), роли, append-only модель
  сообщений и граница `cancel` без стриминга в `tst_chat`,
  `tst_placeholderprovider` (контракт `respond`: асинхронность, эхо, пустая
  история), а также offscreen QML smoke-тест
  `tst_main`, прогоняющий через интерфейс «добавить чат» и «отправить» с фейковым
  провайдером.
- Коллекции LLM-чата (`src/domain/`): `Providers` — неизменяемый список доступных
  для выбора провайдеров (идентификатор и отображаемое имя в C++ и как роли модели
  `id`/`displayName`), с запросом `fresh(id)`, выдающим новый независимый экземпляр
  провайдера; `Chats` — модель сетки независимых чатов (`add`, `remove`, `count`,
  `at`), которая владеет своими `Chat` и создаёт каждый чат из переданного ей
  провайдера.
- `ProviderOffer` (`src/domain/ProviderOffer.h`) — неизменяемое значение «провайдер
  доступен для выбора»: идентификатор, отображаемое имя и рецепт создания нового
  экземпляра провайдера. Это ответ на вопрос «как новый чат получает свежий экземпляр
  провайдера по выбранному id»: `chats.add(providers.fresh(id))`. Рецепт выбран вместо
  готового экземпляра, потому что `Chat` владеет провайдером единолично, а `Provider` —
  QObject и не копируется; так обошлось без фабрик, сервис-локаторов, глобального
  состояния и без изменения контракта `Provider`.
- Модульные тесты `tst_providers` и `tst_chats` (Qt Test + CTest, offscreen,
  детерминированно, сигналы модели через `QSignalSpy`): идентичность предложений,
  независимость выдаваемых экземпляров, владение и освобождение чатов, сигналы
  вставки/удаления строк, границы индексов и сквозной поток «провайдер из списка →
  чат в сетке → стриминг ответа».
- Композиция «провайдер из списка → чат в сетке» безопасна при неизвестном id и
  для устаревших строк: `Providers::fresh` возвращает «нет провайдера», если id не
  предложен или рецепт не смог собрать экземпляр, а `Chats::add` такой провайдер
  отклоняет и чат не создаёт; `Chats::at`, `Providers::idAt` и `displayNameAt` на
  индекс вне диапазона возвращают «ничего» вместо неопределённого поведения.

### Changed

- Локальный прогон quality gates (`scripts/ci-check.sh`, `scripts/static-analysis.sh`)
  стал значительно быстрее:
  - `clang-tidy` и `clazy` распараллелены по числу CPU (`ANALYSIS_JOBS`) и анализируют
    только собственные translation units (`src/`, `tests/`); заголовки проверяются через
    включающие их TU, а сторонний код (LLMQore в `_deps/`) и moc/qml-генерация исключены;
  - тяжёлые необязательные анализаторы (`scan-build`, `iwyu`, `CodeChecker`), которых нет
    в обязательном CI-gate, вынесены в режим `--deep`; `--all` теперь зеркалит CI
    (clang-format, qmlformat, qmllint, clang-tidy, clazy, cppcheck);
  - локальные сборки Debug/Release/ASan/coverage идут через `ccache` — повторные прогоны
    переиспользуют объектные файлы Qt/moc/LLMQore;
  - `conan install` выполняется один раз на `build_type` за прогон;
  - `CodeChecker` получает отфильтрованную базу компиляции (только `src/` + `tests/`).
- Профиль строгих предупреждений Clang вынесен в общую INTERFACE-цель
  `audio-assistant-strict`; `CMakeLists.txt` собирает домен отдельной целью
  `audio-assistant-domain` и линкует её в приложение и тесты (target-based).
  Подавления `-Wno-padded` и `-Wno-unsafe-buffer-usage` вынесены в отдельную
  INTERFACE-цель `audio-assistant-qt-warnings`, которую линкуют только домен и его
  тесты (Qt value-типы дают tail-padding, а moc-диспетчеры индексируют массив
  аргументов сигнала); остальные цели сохраняют полный `-Weverything`-профиль.
- `tests/.clang-tidy` наследует корневой конфиг и смягчает только порог
  `readability-function-size`: макросы Qt Test (`QCOMPARE`/`QVERIFY`) раздувают
  счётчик statements, из-за чего обычные тестовые функции ложно не проходили.
- Стадия Coverage в `scripts/ci-check.sh` отчитывается только по собственному коду
  проекта: сторонний код, подтянутый в `_deps/` (LLMQore), и сгенерированные
  Qt-файлы (`_autogen`, `.qt`, каталоги сборки) исключаются из обхода и из отчёта;
  устаревшие профили перед прогоном удаляются, чтобы `llvm-cov` не зависал.
- `AGENTS.md` реструктурирован: общие правила (~80 строк) в корне, специфичные
  для подсистем — во вложенных `src/AGENTS.md`, `qml/AGENTS.md`, `tests/AGENTS.md`
  (загружаются OpenCode V2 только при работе в соответствующей директории).
- Правила ветвления, changelog и code reuse вынесены в `docs/BRANCHING.md`,
  `docs/CHANGELOG_GUIDE.md`, `docs/CODE_REUSE_POLICY.md`.
- Обновлён `.gitignore`: исключены артефакты покрытия (`*.profraw`, `*.profdata`),
  кеш-директория `.cache/`.
- Обновлён `docs/STATIC_ANALYSIS_TOOLS.md`: состояние инструментов в окружении.
