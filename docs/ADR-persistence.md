# ADR-0002: Зависимость для локального хранения (SQLite)

- **Статус:** принято (adopt)
- **Дата проверки фактов:** 2026-10-18
- **Связанные документы:** `docs/CODE_REUSE_POLICY.md`, `docs/REUSE_CANDIDATES.md`,
  `AUDIO_ASSISTANT_BUILD_MVP.md`, `conanfile.py`
- **Область:** только выбор и подготовка зависимости. Слой хранения (схема,
  миграции, репозитории чатов и сообщений) здесь **не реализуется** — добавлены
  сама зависимость и smoke-тест компиляции/линковки.

## Контекст

Приложению нужно переживать перезапуск: чаты, сообщения и настройки провайдеров
должны храниться локально. Настройки провайдера уже персистятся в плоский
`provider.env` (`ProviderConfigFile`), но список чатов и история сообщений сейчас
живут только в памяти.

Цель этого этапа — зафиксировать **хранилище и способ его поставки (строго через
Conan)**, чтобы последующая реализация слоя персистентности строилась на уже
проверенной основе. Требуется встраиваемая (embedded), кроссплатформенная,
serverless БД без внешнего процесса и без обязательной нативной интеграции под
каждую ОС.

## Решение

Использовать **SQLite** как managed-зависимость Conan:
`sqlite3/3.54.0` из ConanCenter, CMake-цель `SQLite::SQLite3`.

## Карточка кандидата (по `docs/CODE_REUSE_POLICY.md`)

### Решаемая задача и альтернатива собственной реализации

- Даёт: самодостаточный SQL-движок в одном файле БД, транзакции (ACID),
  in-memory режим для тестов, стабильный C-API. Не требует сервера и
  демонизированного процесса.
- Альтернатива — собственная реализация персистентности (свой формат файла /
  сериализация) — отклонена: пришлось бы писать и поддерживать схему, версии
  формата и восстановление после сбоя, что дороже адаптера к готовой БД.

### Точный источник, версия и дата проверки

- URL upstream: <https://sqlite.org>
- URL пакета: <https://conan.io/center/recipes/sqlite3> (ConanCenter)
- Версия: **3.54.0** — самая свежая в ConanCenter на дату проверки
  (`conan list "sqlite3/*" -r conancenter` показал версии до `3.54.0`).
- Источник (из `recipes/sqlite3/all/conandata.yml`):
  `https://sqlite.org/2026/sqlite-amalgamation-3540000.zip`,
  sha256 `68e913b0fe8ec6b4e5f391c594a28872884e80d6cd042a1e50c957be46b5aa4d`.
- Дата проверки: 2026-10-18.

### Лицензия и совместимость

- SQLite распространяется как **public domain** (посвящение в общественное
  достояние; опционально — лицензия на пользование). Рецепт ConanCenter
  объявляет `license = "Unlicense"`. Обе permissive-формулировки совместимы с
  проприетарным и permissive лицензированием продукта.
- Attribution не требуется; файл `LICENSE` поставляется в пакете
  (`<pkg>/licenses/LICENSE`).

### Поддержка платформ и Qt

- SQLite не зависит от Qt (чистый C), совместим с любой версией Qt; целевая
  версия Qt проекта (6.8.3) здесь не ограничивает.
- Linux / Windows / macOS: поддержка есть (тот же исходник амальгамации).
- Android: поддержка есть у upstream, но вне текущего скоупа проекта.
- **Проверено фактически только на Linux/Clang 18** (`conan install` + сборка и
  smoke-тест `tst_sqlite_smoke`); Windows/macOS — заявленная поддержка upstream,
  в этом репозитории не подтверждена.

### Транзитивные зависимости, размер и влияние на сборку

- Транзитивные зависимости: **нет** (опция `enable_icu=False` по умолчанию; при
  включении ICU появится зависимость `icu`).
- Собирается из амальгамации в статическую `libsqlite3.a` (по умолчанию
  `shared=False`). Опции рецепта по умолчанию: `threadsafe=1` (serialized),
  `enable_rtree=True`, `enable_math_functions=True`, `build_executable=True`
  (собирается и CLI `sqlite3`), FTS3/4/5 и JSON1 — выключены.
- Системные линковки, объявленные рецептом: Linux/FreeBSD — `pthread`, `dl`, `m`.
- Влияние на сборку: один раз собирается сам пакет (`--build=missing`) при
  первом `conan install`; на инкрементальную сборку проекта не влияет.
  Заголовок `sqlite3.h` подключается как **SYSTEM**, иначе чужой код уронит
  сборку под `-Weverything -Werror`.

### Тесты, CI, активность сопровождения

- Upstream: очень зрелый проект, регулярные релизы, обширный собственный
  тестовый набор (`TCL`-тесты) и строгие требования к покрытию.
- Conan-пакет собирает и упаковывает библиотеку; собственного набора тестов
  интеграции проект не даёт — проверка интеграции обеспечивается собственным
  smoke-тестом репозитория `tst_sqlite_smoke`.
- Открытых критических issues, блокирующих использование, при обзоре не
  выявлено.

### Соответствие Clang/C++20, `-Werror`, санитайзерам

- Заголовок — C; собирается Clang 18. Под строгим профилем проекта
  (`-Weverything -Werror`) подключается как SYSTEM-заголовок.
- Код покрывается ASan/UBSan в составе наших тестовых целей; библиотека не
  отключает санитайзеры.

### Стоимость адаптера, обновлений и удаления

- Адаптер: слой хранения появится отдельной задачей; здесь API не пишется.
- Обновления: смена версии — правка одной строки `requires` в `conanfile.py`
  (Conan — единственный источник версии).
- Удаление: удалить `requires`, `find_package(SQLite3)`, линковку и smoke-тест.

### Итог

**Adopt** — подключить через ConanCenter (`sqlite3/3.54.0`).

## Отказ от альтернатив (по одной строке)

- **Qt SQL (QSQLITE)**: даёт тот же SQLite, но ставится не через Conan, а вместе
  с Qt (`Qt6::Sql`) — нарушает требование «все зависимости строго через Conan»;
  к тому же Qt на Linux ставится через `aqtinstall`, а не Conan.
- **SQLiteCpp / sqlite_orm**: удобный C++-обёрточный API, но добавляет
  зависимость-обёртку над тем же `sqlite3`; для тонкого слоя хранения проекта
  достаточно C-API, а лишняя обёртка увеличивает граф зависимостей.
- **Системный `libsqlite3-dev`**: не per-user и не пиннится, версия зависит от
  дистрибутива — нарушает «Conan — единственный источник версии».
- **Другой embedded-движок (DuckDB, RocksDB, LMDB)**: избыточен для реляционного
  хранения чатов; SQLite проще, зрелее и компактнее.

## Последствия

- Плюсы: один переносимый статический пакет с permissive-лицензией; нет
  транзитивных зависимостей; in-memory режим упрощает детерминированные тесты
  слоя хранения; Conan — единственный источник версии.
- Минусы/риски: слой хранения, схема и миграции ещё не реализованы — на данном
  этапе dependency подключена и проверена только smoke-тестом; Windows/macOS
  сборки с ней пока не подтверждены в этом репозитории.
