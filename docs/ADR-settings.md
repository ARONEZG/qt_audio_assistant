# ADR-0004: Пользовательские настройки захвата и транскрибации

- **Статус:** принято (adopt)
- **Дата проверки фактов:** 2026-10-20
- **Связанные документы:** `AGENTS.md`, `AUDIO_ASSISTANT_BUILD_MVP.md`,
  `docs/ADR-0001` (захват аудио), `docs/ADR-0003` (Silero VAD),
  `src/domain/CaptureConfig*`, `src/domain/CapturePresets*`,
  `src/domain/CaptureSettings*`, `qml/CaptureSettingsPanel.qml`
- **Область:** хранение и применение пользовательских настроек окна захвата,
  модели/языка/контекста распознавания, VAD и минимальной длительности речи.

## Контекст

До этого изменения параметры распознавания были жёстко заданы в коде или
читались только из окружения:

- кольцевой буфер хранил 30 секунд, и на распознавание уходил весь снимок;
- минимальная длительность речи была `constexpr`-константой 12000 сэмплов
  (0.75 с при 16 кГц);
- модель и язык STT задавались через `POLZA_STT_MODEL` / `POLZA_STT_LANGUAGE`,
  контекст — через `POLZA_STT_PROMPT`;
- пользователь не мог изменить ни одно из этих значений без перезапуска
  приложения с другим окружением.

Нужны настраиваемые параметры с сохранением между запусками, пресетами для
типовых сценариев и применением без перезапуска. При этом операторские запуски
через переменные окружения должны продолжать работать.

## Решение

### Отдельный файл `capture.env`

Настройки захвата и транскрибации хранятся в `capture.env` рядом с
`provider.env` (тот же каталог `QStandardPaths::AppConfigLocation`), а не в
`provider.env`.

Причины:

1. **Разные владельцы и панели.** Endpoint/model/key провайдера чата и параметры
   захвата редактируются в разных панелях. Общий файл означал бы, что каждая
   панель должна сохранять чужие поля, чтобы не потерять их; отдельный файл
   делает сохранение независимым и атомарным.
2. **Разные роли.** `provider.env` хранит endpoint, модель и API-ключ провайдера
   чата; параметры захвата — отдельная роль без секретов. Смешивание расширяет
   поверхность ошибок.
3. **Совместимость.** Формат остаётся тем же KEY=VALUE, поэтому файл можно
   читать как обычный `.env`, а неизвестные ключи игнорируются.

### Модель, язык и контекст — не часть `provider.env`

`POLZA_STT_MODEL`, `POLZA_STT_LANGUAGE` и `POLZA_STT_PROMPT` относятся к
распознаванию, а не к чат-провайдеру. Это отдельная роль (`TranscriptionProvider`)
и отдельный адаптер; у них своя модель (Whisper), свой язык и своя подсказка.
Хранение их в `capture.env` сохраняет SRP и позволяет менять STT-параметры, не
затрагивая конфигурацию чата.

### Буфер фиксированный, окно динамическое

Кольцевой буфер создаётся один раз на **120 секунд** — это максимальное
допустимое окно (`kMaxCaptureSeconds`) и одновременно верхняя граница валидации.
`AudioCapture::transcribeLast()` обрезает снимок до последних
`captureDurationSeconds` секунд (по умолчанию 20).

Причины:

1. **Никаких перестроений на лету.** Буфер — SPSC-структура с фиксированной
   ёмкостью и аллокацией при создании; менять размер при сохранении настроек
   означало бы остановку захвата и сложную синхронизацию с аудиопотоком.
2. **Любое окно доступно сразу.** Пользователь может выбрать 120 секунд без
   перезапуска: данные уже в буфере.
3. **Память предсказуема.** 120 с × 16 кГц × 4 байта ≈ 7.5 МБ на всё приложение;
   это приемлемая цена за мгновенную смену окна.
4. **Окно — это фильтр запроса, а не ёмкость хранения.** Обрезка выполняется на
   потребительской стороне, перед VAD и сетью.

### Пресеты как неизменяемые данные

`CapturePresets` — неизменяемая модель списка (`QAbstractListModel`) из трёх
схем: «Balanced» (20 с), «Long recordings» (120 с), «Quick commands» (10 с,
минимум речи 0.25 с). Выбор пресета только заполняет черновик формы; он не
сохраняет настройки и не меняет пайплайн. Сохранение остаётся явным действием
пользователя.

Причины:

1. Пресет — это стартовая точка, а не скрытая команда: пользователь видит
   значения в полях и может их поправить.
2. Модель неизменяема, поэтому её можно безопасно отдавать в QML и использовать
   как `model` ComboBox без риска рассинхронизации.
3. Новые схемы добавляются в одном месте (composition root), без ветвлений по
   типу в UI.

### Приоритет окружения

Разрешение стартовой конфигурации (`CaptureConfigSource`) использует файл как
базу, а окружение — как override только при явном наличии переменной:

- `POLZA_STT_MODEL`: непустое значение переопределяет модель из файла;
- `POLZA_STT_LANGUAGE`: явно присутствующая переменная переопределяет язык из
  файла (пустая строка — автоопределение, значение — этот язык); при отсутствии
  переменной сохраняется значение из файла (по умолчанию `ru`);
- `POLZA_STT_PROMPT`: непустое значение переопределяет контекст из файла и
  обрезается по краям; отсутствующая или пустая переменная сохраняет значение
  из файла.

Поля окна захвата, VAD и минимальной речи читаются только из файла (с
дефолтами); переменных окружения для них нет, чтобы не плодить второй,
невидимый пользователю источник истины.

### Применение без перезапуска

`CaptureSettings::save()` — единственная мутирующая команда. Она нормализует
черновик, валидирует его, пишет файл и только затем атомарно заменяет состояние
(с сигналами только по изменившимся полям). Composition root подписан на
`saved()` и передаёт новые значения в `AudioCapture::setCaptureOptions()` и
`OpenAiCompatibleTranscriber::setSpeechOptions()`. Отклонённое сохранение не
трогает ни состояние, ни файл.

## Последствия

- Пользователь настраивает окно, модель, язык, контекст, VAD и минимальную речь
  из диалога настроек; значения переживают перезапуск.
- Значение по умолчанию для окна изменилось с 30 до 20 секунд.
- Операторские запуски через `POLZA_STT_*` продолжают работать: явно заданная
  переменная переопределяет сохранённое значение на время запуска, а её
  отсутствие больше не стирает пользовательские язык и контекст.
- `CaptureConfig`, `CaptureConfigFile`, `CaptureConfigSource`, `CapturePresets` и
  `CaptureSettings` покрыты отдельными Qt Test-целями; изменения `AudioCapture`
  и транскрибера — регрессионными тестами.
- Кроссплатформенность: настройки не содержат путей и платформенных API;
  каталог выбирает `QStandardPaths`. Проверено на Linux; Windows/macOS
  подтверждаются CI-матрицей.
