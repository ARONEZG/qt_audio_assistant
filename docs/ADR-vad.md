# ADR-0003: Обнаружение речи (Silero VAD поверх onnxruntime)

- **Статус:** принято (adopt)
- **Дата проверки фактов:** 2026-10-19
- **Связанные документы:** `docs/ADR-0001` (miniaudio), `docs/CODE_REUSE_POLICY.md`,
  `docs/REUSE_CANDIDATES.md`, `AUDIO_ASSISTANT_BUILD_MVP.md`, `conanfile.py`,
  `recipes/onnxruntime/conanfile.py`, `models/silero_vad/`
- **Область:** выбор модели/рантайма и слоя сегментации речи для обрезки тишины
  перед распознаванием; реализация адаптера — в этой же задаче.

## Контекст

Пайплайн захвата пишет последние 30 секунд канонического потока (16 кГц / моно /
f32) в кольцевой буфер, а «Transcribe» отправляет весь снимок на распознавание.
На практике снимок содержит длинные хвосты тишины (микрофон открыт постоянно,
пользователь говорит только часть окна), что:

1. удлиняет запрос к STT и увеличивает потребление токенов/времени;
2. ухудшает качество распознавания на длинных «пустых» аудио.

Нужно определять, где в захваченном окне находится речь, и отдавать в STT только
речевые интервалы. Детектор должен работать в потоке канонического формата
(16 кГц / моно / f32) в реальном времени, не зависеть от ОС и не требовать сети.

## Решение

Использовать **Silero VAD** (`silero-vad` v6.2.1) как встраиваемую ONNX-модель,
выполняемую в **onnxruntime** (CPU), поставляемом через Conan. Поверх неё —
детерминированный слой постобработки (threshold + гистерезис + min-duration),
реализованный чистым C++/STL.

## Карточка кандидата (по `docs/CODE_REUSE_POLICY.md`)

### Решаемая задача и альтернатива собственной реализации

- Даёт: определение вероятности речи на кадр 32 мс, обученную модель без
  ручной настройки энергетических порогов; кроссплатформенный CPU-рантайм.
- Альтернатива — собственная энергетическая обрезка (RMS/zero-crossing):
  отклонена, потому что на уровне MVP уже есть обученная качественная модель,
  а калибровка порогов на наушники/микрофон/шум — отдельный долгий трек
  (см. «Отказ от альтернатив»).

#### Важное примечание о сборке onnxruntime Clang 18

Исходники **1.24.4 не собираются** строгим инструментарием проекта (Clang 18):
`onnxruntime/core/common/cpuid_info.cc` использует GCC-специфичный
`__builtin_cpu_supports("waitpkg")`, который Clang отвергает
(`error: invalid cpu feature string for builtin`). Это известный баг, исправленный
upstream **после** релиза (PR microsoft/onnxruntime#27669, commit `8a08225`).
Более новой версии в ConanCenter на дату проверки нет (1.23.2 содержит тот же
баг).

Решения, проверенные и отклонённые:

- **GCC-пребилд из ConanCenter** (settings gcc 13, libstdc++11, gnu17, Release):
  ABI-совместим с Clang 18/libstdc++, но Conan 2 не позволяет подхватить его под
  Clang-профилем проекта — per-package `-s onnxruntime:compiler=gcc` всё равно
  строит пакет из исходников (`tools.build:compiler_executables` глобально
  переключает компилятор) и падает на том же баге.
- **Ручной патч source-кэша Conan**: чинит сборку, но кэш пересоздаётся из
  tarball при переустановке — не воспроизводимо.
- **Ожидание 1.25+**: задача блокируется неопределённо долго.

Принято решение: **in-repo рецепт `recipes/onnxruntime`** (прецедент —
`recipes/llmqore`) поверх того же ref `onnxruntime/1.24.4`. Рецепт повторяет
ConanCenter-рецепт 1.24.4 один-в-один (тот же tarball, тот же SHA, те же
зависимости и `cmake/onnxruntime_external_deps.cmake`) и добавляет один
минимальный vendor-патч `cpuid_info.cc` — ровно upstream-фикс PR #27669
(замена блока TPAUSE на переносимую проверку CPUID-бита). Всё остальное
(экспорт-патчи ConanCenter, `package_info`, C++ target `onnxruntime::onnxruntime`)
идентично, поэтому возврат к upstream-рецепту — правка одной строки, когда
исправленная версия появится в ConanCenter. Сборка остаётся строго на Clang.

### Поддержка платформ и Qt

- onnxruntime CPU поддерживает Linux (x86_64/aarch64), Windows, macOS — целевые
  платформы проекта. onnxruntime-заголовки — SYSTEM include, поэтому строгий
  профиль `-Weverything -Werror` не падает.
- Silero VAD — чистая вычислительная модель (ONNX-граф: LSTM, 16 кГц/моно/f32;
  вход [1,512] + 64 сэмпла контекста = 576; state [2,1,128]; sr int64), без
  платформенного кода.
- **Проверено фактически только на Linux/Clang 18** (сборка + unit + smoke);
  Windows/macOS — заявленная поддержка upstream, не подтверждена в этом
  репозитории.

### Транзитивные зависимости, размер и влияние на сборку

- onnxruntime тянет существенный граф Conan: onnx, abseil, protobuf, date, re2,
  flatbuffers, boost (headers), safeint, nlohmann_json, eigen, ms-gsl, nsync,
  cpuinfo (+ curl/openssl для телеметрии/модели). Это заметно увеличивает время
  `conan install`/сборки (первый Debug-сбор ~1172 TU) — плата за управляемую
  зависимость вместо vendoring.
- Модель `silero_vad.onnx` — **2 327 524 байта**, вложена как Qt-ресурс
  (`audio-assistant-models`, qrc), в рантайме не скачивается. Бинарь приложения
  увеличивается примерно на это значение (после сжатия rcc — меньше).
- Публичные заголовки аудио-подсистемы **не содержат onnxruntime**: все
  `Ort::*` типы спрятаны за pimpl в `SileroVoiceActivityDetector` (прецедент —
  `MiniaudioCaptureSource`). onnxruntime линкуется PRIVATE.

### Тесты, CI, активность сопровождения

- onnxruntime — активно сопровождаемый upstream (Microsoft), регулярные релизы,
  собственный огромный CI. Пакет в ConanCenter обновляется.
- Silero VAD — активный (snakers4), версия 6.2.1 (октябрь 2025) — самая свежая
  на дату проверки.
- Наш CI: детерминированные unit-тесты (`tst_speechsegmenter`, `tst_vadgate`,
  расширенный `tst_audiocapture` — все на тестовых двойниках, без ONNX) +
  интеграционный smoke (`tst_vad_smoke`) с моделью из qrc и синтетическим

### Соответствие Clang/C++20, `-Werror`, санитайзерам

- Слой сегментации (`SpeechSegmenter`) и гейт (`VadSpeechGate`) — чистый C++/STL,
  компилируются строгим профилем, покрываются ASan/UBSan в общих тестах.
- Адаптер (`SileroVoiceActivityDetector`) читает модель через QFile/QResource
  (Qt Core — PRIVATE-зависимость аудио-библиотеки; публичные заголовки остаются
  Qt-free), исполняет граф через `Ort::Session`.

## Контракт и сегментация

Порт `VoiceActivityDetector` — узкий role-интерфейс: `process(frame512) -> [0,1]`,
`reset()`. Реализация (`SileroVoiceActivityDetector`) скрывает onnxruntime.

`SpeechSegmenter` — чистый конечный автомат по вероятностям кадров:
- **threshold** (0.5) — кадр «речевой», если вероятность >= порога;
- **hysteresis** (0.15) — внутри речевого интервала кадр остаётся речевым, пока
  вероятность >= `threshold - hysteresis` (провал не рвёт фразу);
- **minSpeechFrames** (8 = 256 мс) — интервал короче порога отбрасывается
  (ложная активация);
- **minSilenceFrames** (4 = 128 мс) — пауза короче порога склеивает интервалы
  (внутрифразовая пауза не рвёт предложение).

`VadSpeechGate` режет канонический поток на кадры 512, кормит детектор,
сегментирует вероятности и по интервалам строит keep-mask; `AudioCapture`
применяет её к снимку в `transcribeLast()`, когда гейт подцеплен
(`setVadGate`). Без гейта поведение не меняется (весь буфер уходит в STT).

## Отказ от альтернатив (по одной строке)

- **Энергетическая обрезка (RMS/zero-crossing)**: простая, но требует калибровки
  порогов под устройство/шум и не различает речь и шумные не-речевые звуки.
- **Vosk / Kaldi / whisper VAD**: тяжёлые ASR-ориентированные зависимости, либо
  вне Conan, либо избыточны для задачи «найти речь в окне».
- **Собственный рантайм ONNX (нат. FetchContent/submodule)**: нарушает правило
  «все зависимости строго через Conan» (`AGENTS.md`).
- **Ort extension / AGGRESSIVE = 3 у Silero**: снижение порога — не решение
  проблемы тишины, а только перенастройка чувствительности.

## Последствия

- Плюсы: обученная качественная модель за узким портом; детерминированная
  постобработка без сетей; модель вложена (qrc), сеть не нужна; STT получает
  только речь, что сокращает запрос и повышает точность; onnxruntime за pimpl не
  протекает в публичные заголовки.
- Минусы/риски: заметный рост времени сборки и размера бинаря (существенный
  Conan-граф + ~2.3 МБ модели); in-repo recipe onnxruntime с vendor-патчем
  (временная мера до 1.25+ в ConanCenter); Windows/macOS-сборки не подтверждены.
