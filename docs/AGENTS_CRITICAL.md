# Критические правила — обязательны в каждой задаче

Эти правила не обсуждаются и не «забываются». Они дополняют `AGENTS.md` и
`docs/BRANCHING.md`; при конфликте применяется более строгое правило.
Файл подключается через `opencode.json` (`instructions`) и всегда остаётся в контексте.

## Изоляция

- Каждое значимое изменение — в отдельной ветке от актуальной `main`
  (`feature/...`, `fix/...`, `chore/...`).
- Прямые коммиты и пуши в `main`/`master` запрещены и блокируются git-hook'ами
  (см. `scripts/setup-git-hooks.sh`). Обход — только `--no-verify` в исключительном случае.

## Доставка (часть Definition of Done)

После зелёного `scripts/ci-check.sh` — ОБЯЗАТЕЛЬНО, без ожидания разрешения:

1. `git push` в `origin`;
2. `gh pr create` (или API) с описанием «что + зачем».

## Мерж

- Мерж в `main` — только по явной команде пользователя и только при зелёном CI.

## Порядок действий

1. Прочитай `AGENTS.md`, задачу и затрагиваемый код.
2. Минимальный план + критерии приёмки.
3. Сначала тест, затем минимальное изменение.
4. `scripts/ci-check.sh` — зелёный.
5. Push + PR.
