# Инструкции для AI-агента разработки

Обязательный системный контракт для любого агента, изменяющего репозиторий.
`AUDIO_ASSISTANT_BUILD_MVP.md` — продуктовая задача, этот файл — процесс и архитектурные
ограничения. При конфликте применяется более строгое правило.

При работе с конкретной подсистемой OpenCode загружает её локальный `AGENTS.md`:
`src/AGENTS.md`, `qml/AGENTS.md`, `tests/AGENTS.md`. Правила из этих файлов обязательны
наравне с настоящим.

## 1. Роль и порядок работы

Ты — исполнитель, не автор требований. Работай маленькими проверяемыми инкрементами:

1. Прочитай этот файл, `AUDIO_ASSISTANT_BUILD_MVP.md` и затрагиваемый код.
2. Сформулируй минимальный план и критерии приёмки.
3. Сначала тест, затем минимальное изменение кода.
4. После изменений: `scripts/ci-check.sh` или `scripts/static-analysis.sh` (формат + QML + linters) плюс эквивалентный ручной набор проверок.
5. Сообщи точные команды и результаты; не заявляй о непроверенном.

Не устанавливай пакеты, не меняй публичные контракты, не отключай проверки, не расширяй
объём задачи без явного разрешения. Если инструмента нет — остановись и сообщи что нужно.
Не создавай заглушки ради зелёной сборки.

Правила ветвления, коммитов и changelog: `docs/BRANCHING.md`, `docs/CHANGELOG_GUIDE.md`.

## 2. Toolchain

- **C++20**, без compiler extensions (`CXX_EXTENSIONS OFF`).
- **Clang** — единственный допустимый компилятор. GCC/MSVC — только CI-проверки.
- **Qt 6**, **CMake** с target-based командами, **Ninja**.
- **Qt Test** (`Qt6::Test`) + CTest. Без других фреймворков.
- `CMAKE_EXPORT_COMPILE_COMMANDS` включён.
- Конфигурация обязана упасть с ошибкой на не-Clang.
- Глобальные `include_directories()`, `link_libraries()`, `add_definitions()` запрещены.

## 3. Кроссплатформенность

Целевые desktop-платформы: **Linux, Windows, macOS** — равноправны.
Android — запланирован, но не в текущем скоупе.

- Domain-логика и публичные контракты не зависят от ОС.
- Платформенный код — за узким интерфейсом, отдельные файлы/цели, выбор через CMake.
- Никаких `#ifdef` в domain-коде, жёстких путей, shell-команд, предположений о платформе.
- Переносимые API Qt и STL предпочтительнее нативных.
- Изменение не завершено без CI-сборки на Linux, Windows, macOS.
- Непроверенная платформа = явно указана как неподтверждённая.

## 4. Архитектура: SOLID + «Элегантные объекты»

- **SRP:** один класс — одна причина изменения. UI, orchestration, I/O, domain разделены.
- **OCP:** новые провайдеры — реализации контрактов, не `if` по типу.
- **LSP:** сохраняй предусловия, постусловия и семантику интерфейса.
- **ISP:** небольшие role-based интерфейсы.
- **DIP:** orchestration зависит от абстракций, зависимости — через конструктор.

Правила «Элегантные объекты» (прагматично):
- объекты инкапсулируют данные и поведение;
- зависимости и валидное состояние — при создании;
- неизменяемое состояние и композиция предпочтительнее;
- `static`-методы, `Manager`, `Helper`, `Utils` — избегать;
- `nullptr` как штатный результат — тип-безопасная альтернатива;
- команды меняют состояние, запросы возвращают данные;
- короткий публичный API, защищённые инварианты.

Запрещены: service locator, mutable global state, бизнес-логика в QML, Qt-сигналы как
глобальная шина событий. Сигналы/слоты, parent ownership, Qt idioms — допустимы.
Приоритеты: корректность → проверяемость → простота → SOLID → правила «Элегантные объекты».

## 5. Definition of Done

Работа не завершена, пока:
- требования задачи выполнены;
- тесты каждого добавленного/изменённого модуля проходят;
- compiler warnings и analyzer findings отсутствуют;
- `scripts/ci-check.sh` или `scripts/static-analysis.sh` (или эквивалент) успешен;
- sanitizers без ошибок;
- итоговый отчёт — команды, результаты, пропущенные проверки и причины.

Запрещено объявлять работу готовой при красном gate. Если окружение мешает — честный отчёт
о блокере, не утверждение об успехе.
