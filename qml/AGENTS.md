# Правила QML-интерфейса в qml/

Действуют, когда агент читает или изменяет `.qml`-файлы.
Правила из корневого `AGENTS.md` остаются обязательными; этот файл дополняет их.

## Владение QML

QML-интерфейс — собственный код проекта, свободно изменяемый без правок внешней библиотеки
или форка стороннего приложения.

- Production QML хранится в обычных текстовых `.qml`-файлах.
- Не использовать сгенерированный, бинарный или read-only QML как основу интерфейса.
- Не копировать целиком QML-слой стороннего AI-chat приложения.
- Сторонние QML-модули — только низкоуровневые заменяемые компоненты.

## Архитектура QML

- Собственные экраны зависят от project-owned QML components и C++ view models.
- Бизнес-логика, сеть, хранение, streaming и управление сессией запрещены в QML.
- QML отвечает за представление, bindings и отправку пользовательских намерений.
- Повторяющиеся элементы — в компоненты (message delegate, composer, conversation view).
- Не создавать монолитный `Main.qml`.
- Цвета, размеры, typography, spacing — через design tokens/theme API.

## API и типизация

- Public API компонента: малый, типизированный, документированный.
- Избегать `var`, JavaScript-объектов, динамического доступа по строковым ключам.

## Проверки QML

- `qmlformat` в check-режиме (dry-run с diff).
- `qmllint` без предупреждений.
- `qmltyperegistrar` для проверки регистрации типов.
- QML smoke-test загрузки (offscreen).
- Accessibility, keyboard navigation, масштабирование текста, локализация — часть контракта.

## Platform-specific внешний вид

Реализуется через theme/adapter, не копиями всей страницы.

## Адаптация стороннего QML

Если готовый компонент экономит время — перенести и адаптировать с compatible лицензией.
После переноса: project-owned, архитектура/стиль/тесты проекта. Сохранить источник и лицензию.
Не подменять владение UI git-submodule или зависимостью от upstream-разметки.
